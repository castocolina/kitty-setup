<objective>
Install the structural half of the git policy: a versioned `tools/hooks/pre-push` guard that
rejects history rewrites and direct commits to `master`, wired via a single shared
`core.hooksPath` setting, and regression-tested in a disposable sandbox. The hook lives under
`tools/hooks/` because D-08 fixes that location; the wiring mechanism D-08 left open is settled
here as a `Makefile` target rather than a `my-kitty` subcommand, so no Python runtime is needed on
PATH for the guard to work inside a fresh phase worktree.

Purpose: R0.4 demands the policy be enforced "structurally rather than by acknowledgment"
(D-07). This plan is the phase's **tracer**: it proves the whole hook architecture end to end —
git event → `core.hooksPath` resolution → tracked hook file → verdict → automated test — on one
path, before the two CodeGraph hooks (plan 02) expand out from it. If `core.hooksPath` did not
resolve per worktree, or a copied hook did not fire from a sandbox, that dead end surfaces after
one commit instead of after three hook files and a doc rewrite.

Output: `tools/hooks/pre-push`, `tests/unit/test_git_hooks.py`, a `Makefile` `hooks:` target, and
`core.hooksPath` set in this repo's shared git config.
</objective>

Honest scope, carried verbatim into the hook header and into `AGENTS.md` (plan 01-04): this is a compliance guard for cooperating agents, not a security boundary — `git push --no-verify` bypasses any client-side hook. |
