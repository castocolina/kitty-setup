hook is permitted, then add a versioned `tools/hooks/pre-push` guard that rejects history rewrites
and unauthorised `master` pushes, wired via a single shared `core.hooksPath` setting, and

fresh phase worktree.

(D-07). This plan is the phase's **tracer**: it proves the whole hook architecture end to end —

test — on one path, before the two CodeGraph hooks (plan 02) expand out from it. If `core.hooksPath`

**Step 2 — GREEN.** Create `tools/hooks/pre-push`, mode 0755. Prelude per house style:
`#!/usr/bin/env bash`; a header block naming the invoking git event (`git push`), the argv contract
(`$1` remote name, `$2` remote URL), the stdin contract (one line per ref,
`<local_ref> <local_sha> <remote_ref> <remote_sha>`), and one line stating that this file is shell
because it is a git-invoked hook entry point permitted by the shell allow-list in the repo's
canonical instruction file's `## Stack` section. Name the *section*, not the filename: the canonical
file changes from `CLAUDE.md` to `AGENTS.md` in wave 4 and a filename here would go stale.
Then `set -euo pipefail`;
`REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"` (two levels, because hooks sit
one deeper than `tools/*.sh`) and `cd "${REPO_ROOT}"`; `log() { printf '[pre-push] %s\n' "$*"; }`
plus a second helper `err() { printf '[pre-push] %s\n' "$*" >&2; }` with an inline comment saying
a rejection is diagnostic output and therefore goes to stderr, which is why `log`'s stdout
semantics are not changed.

Define `ZERO_SHA="0000000000000000000000000000000000000000"`. Read stdin line by line into
`local_ref local_sha remote_ref remote_sha`. Every nested git command inside the loop takes its
stdin from `/dev/null`, because git supplies the ref list on fd 0 and a nested command that read
stdin would silently swallow the remaining ref lines.

For each line:
  - When `local_sha` equals `ZERO_SHA` the push is a ref **deletion**; task 3 settles that policy.
    For now, `continue`.
  - When `remote_sha` equals `ZERO_SHA` the remote ref does not exist yet, so there is nothing to
    compare against and the rewrite guard does not apply; `continue` past the ancestor test. Task 3
    settles what this means for `master` specifically. Cite `01-RESEARCH.md` Pattern 2's Limits.
  - Otherwise run the ancestor test inside an `if ! git merge-base --is-ancestor "$remote_sha" "$local_sha" </dev/null; then`
    guard — the `if !` form is required because a bare non-zero exit under `set -e` would abort the
    script with no diagnostic. On rejection: `err` a verdict line that names the ref **and contains
    the literal word `non-fast-forward`**, so a test can tell this guard apart from task 2's master
    guard; then bare indented `printf` lines enumerating how to proceed (push a new branch, or merge
    instead of rewriting); then `exit 1`. Carry an inline comment citing `01-RESEARCH.md` Pattern 2.

End the script with an explicit `exit 0`.
