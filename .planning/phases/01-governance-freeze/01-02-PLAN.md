<objective>
Automate the CodeGraph index lifecycle with two non-blocking git hooks: `post-checkout` builds an
index in a freshly created phase worktree, `post-commit` refreshes it incrementally.

Purpose: R0.6 and ROADMAP criterion 7 require this to be **demonstrated, not asserted** — a
CodeGraph failure must warn without aborting either operation. That is a behavioural claim a grep
cannot settle, so it is tested. This plan expands out from plan 01-01's proven
`core.hooksPath` → tracked-hook-file → sandbox-test path; the architecture is already verified, so
the work here is two more hooks on the same rails.

Both hooks live under `tools/hooks/` alongside plan 01-01's guard, per D-08's fixed location. The
Stack allow-list that permits them was already widened in plan 01-01 (wave 1), so these files are
created under a rule that already names them.

**Two contracts the previous draft got wrong, corrected here.** (1) A *successful* hook emitted no
tag: `codegraph init`'s output was discarded and `sync -q` is silent by design, yet the acceptance
criteria demanded literal `[post-checkout]` / `[post-commit]` tags from the live run. Both hooks now
log a tagged success line, which makes the happy path observable and also makes R0.6's required
**warning** behaviour assertable rather than merely hoped for. (2) "Never blocks" covered absence and
eventual non-zero exit but not a process that never returns; both calls now run under a bounded,
overridable timeout, and the `post-commit` case is proven with a sleeping shim.

Output: `tools/hooks/post-checkout`, `tools/hooks/post-commit`, and eight new cases in
`tests/unit/test_git_hooks.py` (bringing the module to 18). **One commit, at the end of the plan**
(R0.10 / D-16) — the RED→GREEN transitions below are verified states to record, not commits.
</objective>
