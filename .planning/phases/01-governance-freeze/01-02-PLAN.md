<objective>
Automate the CodeGraph index lifecycle with two non-blocking git hooks: `post-checkout` builds an
index in a freshly created phase worktree, `post-commit` refreshes it incrementally.

Purpose: R0.6 and ROADMAP criterion 7 require this to be **demonstrated, not asserted** — a
CodeGraph failure must warn without aborting either operation. That is a behavioural claim a grep
cannot settle, so it is tested. This plan expands out from plan 01-01's proven
`core.hooksPath` → tracked-hook-file → sandbox-test path; the architecture is already verified, so
the work here is two more hooks on the same rails.

Both hooks live under `tools/hooks/` alongside plan 01-01's guard, per D-08's fixed location, and
plan 01-04 amends the Stack allow-list to name that directory.

Output: `tools/hooks/post-checkout`, `tools/hooks/post-commit`, and six new cases in
`tests/unit/test_git_hooks.py`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tracked `tools/hooks/*` → the committing/checking-out shell | Hook scripts execute with the invoking user's privileges, with no sandbox |
| `codegraph` binary → hook process | An external tool invoked on every commit; its failure must not become the repo's failure |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-02 | Elevation of Privilege | `tools/hooks/post-checkout`, `tools/hooks/post-commit` | low | accept | Git hooks are plain files with no sandboxing. Accepted: the mitigation is code review of `tools/hooks/*` changes, which this repo applies to every tracked file, and both hooks here are thin — an argv/flag test plus one guarded external call — which bounds the review surface. A general git-hooks caveat, not specific to this design (`01-RESEARCH.md` Security Domain). |
| T-1-04 | Denial of Service | `codegraph` invocation inside `post-commit` | low | mitigate | A hanging or failing index tool would otherwise block every commit in the repo. Mitigated structurally: `command -v` guard, `\|\| log warning` suffix on the invocation, no `exit 1` on any path, and an explicit terminal `exit 0` — each asserted by this plan's verify gates and by the failing-shim and absent-binary tests. |

No package-manager install occurs in this plan, so no `T-1-SC` supply-chain row applies. No auth,
session, or network surface exists; none was invented to fill the template.
</threat_model>
