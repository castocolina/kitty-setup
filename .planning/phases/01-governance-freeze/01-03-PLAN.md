Order is load-bearing: archive FIRST, then stage, then move. The archive command resolves the change
by name inside `openspec/changes/`, so running it after the relocation would leave it with no root —
and the staging step between them is what makes the move possible at all.

**Run with `set -o pipefail` in effect** for every pipeline below (this repo's own shell convention,
`tools/setup.sh:16`). Without it a failing `find`, `sort` or inner `sha256sum` can still leave the
outer command successful, and the checksum invariant would be measuring nothing.

Step 1 — record the pre-state so the post-conditions are provable rather than assumed.
Create one scratch directory for the whole task:
`scratch="$(mktemp -d "${TMPDIR:-/tmp}/kitty-setup-01-03.XXXXXX")"`. Do **not** write to a bare
`$TMPDIR`: on Linux `TMPDIR` is commonly unset, and under `set -u` the expansion aborts while
without it the path collapses to `/pre.txt`. Then:
  - `git ls-files openspec > "$scratch/pre.txt"` — git's own exit status is checked before anything
    counts the lines; take the count with `wc -l < "$scratch/pre.txt"`.
  - `git ls-files -s openspec | sha256sum > "$scratch/pre-index.txt"` — the staged blob hashes, so a
    content change anywhere in the tree is detectable independently of paths.
  - A checksum of the specs tree specifically:
    `find openspec/specs -type f -print0 | sort -z | xargs -0 sha256sum | sha256sum`.
Record all three values in this plan's SUMMARY.

Step 2 — run `openspec archive phase1-curated-bindings-revert-defaults --skip-specs -y` from the
repo root. Expect exit 0 and the line "Skipping spec updates (--skip-specs flag provided)." Do
NOT author any of the change delta's validator fixes: `openspec validate` reports 6 errors and 1
info on that delta and they are never fixed, because rewriting frozen specs is out of scope
(D-01/D-03, and PROJECT.md's own out-of-scope list). Any task anywhere in this phase that
proposes resolving those validator findings contradicts a locked decision.

Step 3 — recompute the specs checksum. It must equal the pre-state value: `--skip-specs` leaves
the main specs byte-identical, which was reproduced live in a sandbox. If it differs, stop and
report a deviation; a changed specs tree means the wrong flag ran.

**Step 4 — stage the archive's own effects. This step is mandatory and its omission is why the
previous draft did not run.** `openspec archive` moves files in the *working tree* without touching
the index: execution left eight paths as ` D` (unstaged deletions) and the new
`changes/archive/<date>-…/` directory as `??` (untracked). Run `git add -A openspec` and expect a
rename-only change set — execution reported "8 files changed, 0 insertions(+), 0 deletions(-)".
Confirm with `git status --porcelain openspec` that nothing remains unstaged or untracked under that
path before proceeding.

Step 5 — `mkdir -p .planning/legacy`. This is also mandatory: `git mv` does not create the
destination's parent directory, and `.planning/legacy/` does not exist in this repo today.

Step 6 — `git mv openspec .planning/legacy/openspec`. Use `git mv`, not `mv` plus `git add`, so
the rename is recorded in the index and the whole step is revertible with one `git revert`.

Step 7 — prove the move was a pure rename, not a rewrite. Three checks, all against the index:
  - `git ls-files .planning/legacy/openspec > "$scratch/post.txt"`, then compare
    `wc -l < "$scratch/post.txt"` with the step-1 count. They must be equal (execution measured
    145 → 145 for the whole repo).
  - `git diff --cached --name-status HEAD -- openspec .planning/legacy/openspec` — **every** row must
    be `R100`. Both sides of the move must be in the pathspec: with only the destination in it, git
    reports `A` rows with non-zero numstat and the check is guaranteed to fail on a *correct*
    execution. That is exactly what the previous draft's
    `git diff --name-only HEAD -- .planning/legacy/openspec/specs` did, and it is deleted.
  - `git ls-files -s .planning/legacy/openspec | sha256sum` — compare with `pre-index.txt`. Because
    `git ls-files -s` prints `<mode> <blob> <stage>\t<path>`, the paths differ and the hashes will
    **not** match; normalise by stripping the `.planning/legacy/` prefix from the post-move listing
    before hashing, and record both the raw and the normalised comparison in the SUMMARY. If the
    normalised hashes match, every blob is byte-identical.

Step 8 — confirm `openspec` no longer exists at the repo root.
