<objective>
Make the shell-completion script an artefact this project generates and owns, produced at install
time inside the tool venv where `argcomplete` actually lives (D-01, D-02, D-03), and removed on
uninstall unless `--keep-kitty` preserves it.

Purpose: R1.1 is the one requirement that gates two phases' merges — `make doctor` is red today on
exactly one check, and that check is this one. This plan builds the **producer half**: the file
exists, it is provably current, and its lifecycle is owned. The **consumer half** — the rc block that
sources it and the doctor check that verifies it — is plan `02-02`. Splitting there is deliberate:
everything in this plan is purely additive, so no existing test changes meaning and `make test`
cannot go red for a reason this plan invented.

Output: `installer.write_completion_script()` / `remove_completion_script()`, the `cli_install` and
`cli_uninstall` wiring, a new unit module pinning the byte-match contract and the U-3 correction, and
`tmp/h30-argcomplete-static/` recreated inside the repo per the mantra.

<flagged_assumptions>
- **Per-shell filenames are a judgement, not a measurement (research A2).** `--shell bash` and
  `--shell zsh` produce **byte-identical** output at 2685 bytes in argcomplete 3.7.2 (tool venv) and
  3.6.3 (repo venv) — re-measured in the repo venv while this plan was written: both 2685 bytes,
  equal as strings, first line `#compdef my-kitty`. One shared file would work today. This plan still
  writes `my-kitty-completion.bash` and `my-kitty-completion.zsh`, because doctor (`02-02`) then
  byte-checks the file for the shell it is actually running in, and because a future argcomplete that
  diverges the two outputs would break a shared file silently. Cost: one extra 2.7 KB file. Recorded
  so a reviewer does not read the duplication as an oversight.
- **`XDG_DATA_HOME` is not honoured, deliberately.** D-01 names the literal
  `~/.local/share/kitty-setup/`. Measured: `XDG_DATA_HOME` is honoured nowhere in `src/`, while
  `XDG_CONFIG_HOME` is (`scenes/recipe.py:49-53`). The literal path is consistent with the three
  existing installer constants (`DEFAULT_DEST:31`, `SYMLINK_PATH:33`, `DESKTOP_PATH:34`). The
  `home: Path | None = None` injection point every other module offers is added anyway, because the
  tests need it.
- **The idiomatic drop-in locations were considered and are out.** `~/.local/share/bash-completion/`
  exists on this host and `~/.local/share/zsh/site-functions` is already in the host's zsh `fpath`
  (`~/.zshrc:12`); either would need **no rc line at all**. D-01 chose an owned directory plus an
  explicit source line so both halves are checkable. Locked — recorded only.
- **Tying the completion file's removal to `do_kitty` is a decision this plan makes.** §R1.1 ¶5 of the
  research left it open ("config branch or its own — state which"). `do_config` is wrong: `make clean`
  passes `--keep-kitty --keep-backups` and *not* `--keep-config`, so the completion of a surviving
  binary would be deleted by the safe verb. `do_kitty` is the only existing condition `make clean`
  suppresses. The file is not part of the kitty.app footprint, so it gets its own step in
  `cli_uninstall` guarded by the same `do_kitty` boolean rather than being buried inside
  `remove_kitty_install()`, whose name means something else.
- **This plan leaves `my-kitty doctor` still red.** `_check_completion` is untouched here and still
  looks for the helper on PATH. That is expected and is `02-02`'s work. Nothing in this plan may claim
  R1.1 is closed.
- **Supply-chain fact, not a defect (carry into the SUMMARY).** `tools/setup.sh:55` runs
  `uv tool install --reinstall --force .`, which resolves outside `uv.lock` — the installed tool venv
  carries argcomplete **3.7.2** while `uv.lock` pins **3.6.3**. From this plan onward, an unreviewed
  argcomplete version generates shell code the user's rc will source on every login. The byte
  comparison `02-02` adds to doctor is the control that makes such a change visible.
</flagged_assumptions>
