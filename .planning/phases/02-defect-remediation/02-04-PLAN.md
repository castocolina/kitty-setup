<objective>
Close the phase's one genuine vulnerability: pane 0's `cwd` is interpolated into a string a shell then
parses, so a scene TOML becomes arbitrary code execution in the user's own interactive shell (D-08).
Give pane 0's `cmd` the `bash -lc` semantics every other pane already has, and replace three unguarded
`int(result.stdout.strip())` calls with one shared helper that raises a clean error (D-13).

Purpose: R1.4 reads like a formatting nicety and is not. Reproduced in-process with the kitten stubbed:
`Pane(cwd="/tmp/my dir; touch /tmp/PWNED")` produces the payload `cd /tmp/my dir; touch /tmp/PWNED\n`,
and the reused shell runs both halves. Scene TOML is user data, but it is also anything seeded, shared,
or copied from an example — which makes this an input-validation defect in ASVS V5 terms, not a quoting
preference. The `int()` guard rides along because `launcher.py:258` sits inside the same
`_fill_current_tab` function this plan is already editing, so separating them would put two plans on one
function and force an extra wave for nothing.

Output: `shlex.quote` on both pane-0 payloads, `bash -lc` for pane-0 `cmd`, a `_window_id_from` helper at
the three unguarded sites, unit cases pinning each payload string, one real-kitty case proving the
quoting is the *right* quoting, and `tmp/h33-minors/` recreated in the repo.
</objective>

<flagged_assumptions>
- **`bash -lc <cmd>` is close to pane 1+'s semantics but not identical, and the difference is visible
  (research A3, MEDIUM confidence).** `bash -lc` spawns a *child* bash in the reused window. The seeded
  examples use the `… ; exec bash` idiom (`examples/scenes/dev.toml`, `docker.toml`, `edit.toml`); under
  `bash -lc` that `exec` replaces the **child**, so on exit the user lands back in the original shell
  rather than losing the pane. For pane 1+ the `--hold` flag holds the pane instead. The behaviours are
  close, not equal. R1.4 requires the `bash -lc` semantics explicitly, so the alternative — leaving
  pane 0's `cmd` typed raw — fails the requirement. Record the difference in the SUMMARY and cover it
  with the integration assertion rather than reasoning about it.
- **Only the `send-text` path is vulnerable, and the fix must not spread.** `_launch_argv`
  (`launcher.py:135-138`) builds `--cwd=<raw>` as a separate argv element consumed by `subprocess` with
  a list and `shell=False`. No shell parses it. Quoting there would insert literal quote characters into
  a path. A gate below asserts `_launch_argv` is untouched.
- **`launcher.py:172` is already correct and is the source of the shared predicate.** It reads
  `int(raw) if raw and raw.isdigit() else None`. The three unguarded sites (`:258`, `:373`, `:396`)
  should adopt that same rule through one helper rather than each growing its own.
- **`_fill_current_tab`'s signature is positional and easy to get wrong when writing the tests.** It is
  `(layout, tab_title, tab_accent, panes, *, to, default_cwd, origin_window)` at `launcher.py:201-210`,
  and `Pane`'s field order is `['title', 'cmd', 'cwd', 'bg']`. Both were measured; get them from the
  file rather than from memory.
- **The integration sentinel must not be `/tmp/PWNED`.** Use a path inside pytest's `tmp_path` so a
  stale file from an earlier run cannot make the case pass or fail for the wrong reason, and so nothing
  is written outside the test's own scratch. The unit tests may keep the literal `/tmp/PWNED` inside the
  *input string* they assert on, because they never execute it — the kitten is stubbed.
</flagged_assumptions>
