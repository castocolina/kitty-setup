<objective>
Make the config-parse check tell the truth about itself (D-09) and make doctor's three "skipped"
results actual SKIP states (D-13).

Purpose: the parse check is the one gate standing between a mutated `kitty.conf` and the user's next
kitty start, and today it reports a flag that does not exist, discards the only diagnostic that says
what went wrong, and rolls back half of what it changed. Doctor's three false FAILs are grouped into
the same plan because they live in the same file and the same function family — `_check_parse` at
`doctor.py:89-98` carries both the wrong label and one of the three false FAILs, so splitting them
would put two plans on one function.

Both are in scope for ASVS V14: the parse check is "validate the config we wrote before trusting it",
and the measured finding that it cannot see a **missing `include`** is a real gap in that control.

Output: `tmp/h34-parse-check/` recreated **first**, reproducing both defects before any edit; a RED
commit holding every new case across `test_config_updater.py` and `test_doctor.py`, proven failing from
its own tree; then a `ParseCheckResult` dataclass, a rename-aside payload rollback state machine, an
error message that names the real, untruncated command and carries the parser's stderr, a doctor label
derived from the result, and three real SKIPs.
</objective>

  <action>
Implement the rollback as an explicit state machine. `install()` currently `rmtree`s the previous payload
at `:237-238` **before** `copytree` at `:239`, so by the time the parse check fails at `:273` there is
nothing to restore — a true rollback needs the previous directory moved aside rather than deleted, and it
must survive a failure at every step, not only the parser's rejection.

1. **Aside.** If a previous payload exists, `Path.rename` it to a sibling with a `.rollback` suffix — a
   sibling, so it is on the same filesystem and the rename is atomic.
2. **Copy.** `copytree` the new payload into place, then `_select_clear_variant` as today.
3. **Mutate and check.** The existing conf mutation and parse check, unchanged apart from task 1.
4. **Commit.** Only after the parse check passes — or when no check runs — `rmtree` the aside.
5. **Roll back.** On any failure in steps 2-3 — `copytree` raising, the conf mutation raising, or the
   parser rejecting — remove the partial target if it exists, rename the aside back if there is one, and
   re-raise: the parser's rejection as the `ConfigUpdaterError` carrying the full command and stderr,
   anything else as the original exception.
6. **Failed restore.** If renaming the aside back itself fails, do **not** delete the aside — it is the
   only copy of the user's previous payload. Raise `ConfigUpdaterError` naming the aside's path and
   chained to the rename error, so the user can restore by hand.

The invariant is that the previous payload is never destroyed before the new one is accepted: on every
failure path it is either back in place or still at the named aside path. Structure the control flow
with a `try` that restores and re-raises — `try`/`except` with a bare `raise`, or `try`/`finally` driven
by a success flag, whichever reads cleaner — and no suppression comment; `.claude/conventions.md`
forbids them.

The five cases this turns green were written in task 1 step 1 and are in the RED commit; this task
changes no test.

behaviour is wrong once stated; both were previously unstated.
