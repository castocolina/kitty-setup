**WR-02. Decision: a portable-literal rule, with a fallback to the argv path. This amends D-08.** It was
weighed against the alternatives with measured evidence.

- **Research.**
  - `02-04` sends `cd {shlex.quote(p0.cwd)}\n` (`launcher.py:269`) and
    `bash -lc {shlex.quote(p0.cmd)}\n` (`:280`) through `kitten @ send-text`.
  - `shlex.quote` emits POSIX single-quote syntax. fish treats `\'` and `\\` as escapes *inside*
    single quotes, so a typed line holding `\'` ends fish's quoted word early.
  - kitty's `send-text` documentation says the TEXT argument follows Python escape rules, while
    `--stdin` and `--from-file` send text as-is.
  - **So through `send-text` the value must hold `\\'`, not `\'`** (cross-AI review round 3,
    measured in round 4 below). kitten decodes `\\` to `\` and `\'` to `'`. 02-REVIEW.md's TOML
    payload `"/a\\'\"; …"` gives a value with one backslash, which reaches fish as a plain `'`
    and runs nothing. Its evidence typed the line straight into fish, not through kitten. The
    exploit is the doubled TOML form `"/a\\\\'\"; …"`.
- **Experiment.** Hermetic, with fake HOMEs and no live kitty. The kitten binary ran only against a
  fake socket, in a short `mktemp` directory. The results:
  - Quoting today:
    - Typed straight into fish `--no-config`, with no kitten in between, the review's payload in
      `cd {shlex.quote(cwd)}` runs (`PWNED=True`).
    - The same line in bash and zsh is one argument.
    - `bash -lc {shlex.quote(cmd)}` shifts the same way in fish.
    - **Through kitten** (round 4, 2026-11-03): kitten 0.49.2 against a fake socket, the
      delivered line then piped to fish `--no-config --private`, bash `--noprofile --norc` and
      zsh `-f`, and also typed into an interactive fish on a pty. For HEAD's
      `cd {shlex.quote(v)}\n`:
      - `v` holding `a\'"; touch S; #` (one backslash) is delivered as `cd '…/a'"'"'"; touch S; #'`,
        one word everywhere: no sentinel in any shell;
      - `v` holding `a\\'"; touch S; #` (two) is delivered as `cd '…/a\'"'"'"; touch S; #'`:
        fish runs `touch S`, piped and on the pty; bash and zsh do not.
  - Portable values, **single-quoted**: a value with no `'`, no `\` and only printable characters,
    wrapped as `'<value>'`, is the same single word in bash, zsh and fish.
  - **`shlex.quote`'s bare form is not portable** (cross-AI review round 1, re-measured
    2026-11-03 with `printf '%s\n' <word>` in a fake HOME). `shlex.quote` leaves a word bare when
    it holds only `\w@%+=:,./-`:
    - `=bash` gives `/usr/bin/bash` in zsh 5.9.2 (`EQUALS`, on by default) and `=bash` in bash
      and fish;
    - `%self` gives the shell's PID in fish 4.6.0 and `%self` in bash and zsh;
    - `/x/a==bash` gives `/x/a=/usr/bin/bash` in zsh with `magicequalsubst`, an option users
      set, and is unchanged elsewhere.
    - All three, written `'<value>'`, came back unchanged in bash, zsh (with and without
      `magicequalsubst`) and fish.
  - Kitten's decoding, on the fake socket: `\x01` arrived as byte 0x01, `\\` as one `\`, and `\n` as
    a newline. Round 4 added `\'`, which arrives as `'`, and `\\'`, which arrives as `\'`. kitten
    0.49.2 puts the decoded text in the payload's `data` field as `base64:…`.
  - The line editor: the decoded payload (`cd '/tmp` then Ctrl-A, then `touch <sentinel>; `, then
    Ctrl-E, then `'`), fed through a pty to a real interactive shell, runs the payload in bash
    (`--norc`) and zsh (`-f`), with `PWNED=True`.
    - **It runs in fish too** (round 4, re-measured with a positive control: a `touch <control>`
      line typed first, then the payload; control and sentinel both appeared in fish 4.6.0, bash
      and zsh). Planning's earlier "does not run in fish" had no control. An interactive fish 4.6
      on a pty reads no typed input for about 10 s when nobody answers its primary-DA query
      (`\e[0c`). Measured: about 11.1 s unanswered, 1.0 s when the driver replies `\e[?62;22c`.
    - **This vector reaches the host's own login shell, whichever of the three it is**, which is
      why the rule refuses the backslash, not only the quote.
- **Alternatives, weighed.**
  - *Shell-aware quoting* (detect the pane's shell): **rejected, measured unsound.**
    - While the scene runs, `kitten @ ls` reports `my-kitty` itself as the origin window's foreground
      process.
    - The window's `cmdline` and `$SHELL` describe the login shell, not a nested one. A bash window
      running `fish` reads as bash.
    - A wrong guess re-opens the injection, and there is no signal to check the guess against.
  - *Sending with `--stdin`*: removes the escape decoding only. The fish quote shift remains, because
    it is a shell-parser problem.
  - *Refusing the scene outright*: loses a working scene over a value the argv path handles safely.
  - *Chosen: fall back to the new-tab path* (`launcher.py:395` onward). It carries the values as argv
    elements — `--cwd=<raw>` and `bash -lc <cmd>` — which no shell parses. It is already the path for
    a non-solo tab, so its behaviour is tested and known.
- **The rule.** A value is typeable iff every character satisfies `str.isprintable()` and none is `'`
  or `\`.
  - `isprintable()` is `False` for control characters, newline, tab and Unicode format characters
    such as U+202E (right-to-left override), so bidi tricks are refused too.
  - Applied to the typed `cd` target (the normalised absolute path; see WR-03) and to `cmd`. The
    typed string is what must be safe.
  - **A typeable value is always sent single-quoted**: `f"cd -- '{target}'\n"` and
    `f"bash -lc '{cmd}'\n"`, never through `shlex.quote`.
    - Inside single quotes, bash and zsh expand nothing. fish processes only `\'` and `\\`, which
      the rule excludes.
    - So the typed word is the value, byte for byte, in all three shells. That is the property the
      bare form above lacks.
- **Where it applies.** In `launch_scene`, after `_origin_tab_is_solo` has chosen the fill path, and
  before `_fill_current_tab` is called. So the stderr note prints only when the rule changed the
  outcome. The note is one line:
  `my-kitty scene launch: pane 0's cwd or cmd cannot be typed into the current shell unchanged (a
  quote, a backslash, a control or format character, or a cwd that is not an absolute path free of
  $); opening the scene in a new tab instead`.
  The scene's return code is unchanged by the fallback itself.
- **A NUL cannot take the fallback, so the loader refuses it** (cross-AI review round 2).
  - *Research.* TOML basic strings accept `\u0000`. Every pane value reaches `subprocess.run` as an
    argv element through `_client.kitten_at`. CPython refuses an argv element holding a NUL. Neither
    `_launch_named_scene` nor `_launch_inline_scene` catches `ValueError`; they catch `ColorError`
    and `SceneClientError` only.
  - *Experiment*, at `6e6b863`, in a scratch `XDG_CONFIG_HOME` with `_resolve_kitten_binary`
    pointed at `/bin/true` and no kitty:
    - `tomllib` read `cwd = "/tmp/a\u0000b"` as `'/tmp/a\x00b'`, and `load_scene` accepted it in
      `cwd` and in `cmd`;
    - `cli_scene_launch` then raised an uncaught `ValueError: embedded null byte` for both.
    This is pre-existing on both paths and for every pane. The fallback would not cure it, because
    the fallback is that same argv path.
  - *Decision.* `recipe._require_str`, which every recipe string goes through, raises
    `SceneRecipeError` when the value holds a NUL, naming the key. `_launch_named_scene` already
    prints that error as one `my-kitty scene launch: …` line and returns 1. It does so before
    `launch_scene` runs, which is the promise `load_scene`'s docstring already makes for every schema
    violation.
  - *Inline mode needs nothing.* A `--pane` value comes from the process argv, which cannot hold a
    NUL.
  - *Alternatives, weighed.*
    - Catching `ValueError` around `kitten_at`: rejected. The panes before the bad one are already
      launched, which leaves the half-built tab that `load_scene` exists to prevent.
    - Refusing it only in the pane-0 predicate: rejected. Panes 1 and later, and `tab_title`, die the
      same way.
  - *Cost:* none. No recipe can use a NUL today without the traceback.
  - Step 0's real-kitty run proves it: red against HEAD's loader with the `ValueError`, green
    against `prototype_recipe.py`.
- **Scope honesty.**
  - Measured in bash, zsh and fish, the three shells R1.7 names.
  - For any other shell, the typed words hold no quote, no backslash and no control or format
    character, and sit inside single quotes, which removes every construct measured to shift or
    expand. The residual risk there is a `cd` that fails, not a command that runs. That is stated in
    D-08's amendment and is not claimed as measured.
- **Cost.**
  - A pane-0 `cmd` that contains a single quote, such as `git log --format='%h'`, now opens the scene
    in a new tab rather than filling the current one.
  - A pane-0 `cwd` that is `~`-leading, holds a `$`, or is relative does the same (WR-03 below).
  - No shipped example is affected (`examples/scenes/`, checked 2026-11-03):
    - none sets a pane-0 `cwd`;
    - the only multi-pane example with a pane-0 value is `ai-claude.toml`, whose
      `cmd = "claude-opus"` is typeable and now types as `bash -lc 'claude-opus'`;
    - `edit.toml` is single-pane, so it never takes the fill path.
  - `02-04`'s `test_pane0_roundtrip_cmd_with_embedded_quotes` asserted the opposite. It is **deleted
    and inverted** in RED as the `cmd_quote` item of `pane0_untypeable_falls_back`, because the
    behaviour it pinned is exactly the injection surface in fish.

**WR-03. Decision: type only an absolute, `$`-free `cwd`, normalised, as `cd -- '<path>'`. Every
`cwd` that kitty would expand or resolve takes the argv path, so kitty gives it the same meaning it
gives every other pane.** This replaces the first-draft decision, "expand in Python, in kitty's
order, then `./` before a relative target", which cross-AI review round 1 showed is not equivalent.
- **Research.**
  - kitty 0.49's `Child.__init__`, disassembled through `kitty +runpy` with no window, applies
    `os.path.expandvars(os.path.expanduser(cwd))`. That is what `launch --cwd` does for every other
    pane.
  - Upstream `kitty/child.py` (read 2026-11-03) adds the context:
    - the line is `cwd = os.path.expandvars(os.path.expanduser(cwd or os.getcwd()))`, then
      `self.cwd = os.path.abspath(cwd)`;
    - it runs in kitty's own process, before the child's environment is built. So `~` and `$VAR`
      expand with **kitty's** `os.environ`, and a relative path resolves against **kitty's**
      working directory.
  - The launcher sees neither. It sees its own environment and the reused shell's directory. Those
    differ from kitty's whenever HOME or a variable was changed or exported after kitty started, or
    the shell has `cd`'d away from kitty's start directory.
  - zoxide's `__zoxide_z` template handles `-- dir`, so a `cd` wrapper that users alias keeps
    working. Without `--`, a missing directory becomes a fuzzy zoxide query, which is why `--`
    stays even though every typed target is now absolute.
- **Experiment** (bash, zsh, fish, each with a fake HOME). Every row below is a typed relative or
  `-`-leading target, so every row is now an argv-path case:

  | Command | Outcome |
  |---------|---------|
  | `cd '~/d1'` | fails in all three |
  | `cd '-x'` | fails in bash and fish |
  | `cd -- '-x'` | works in all three |
  | `cd -- -` | means OLDPWD in bash and zsh |
  | `cd -- +1` | reaches zsh's directory stack |
  | `cd -- sub` | follows `CDPATH` in bash and fish |
  | `cd -- ./sub` | correct in all three |

- **The change.**
  - Pane 0's `cwd` is typeable iff `os.path.isabs(cwd)`, no `$` occurs in it, and
    `_typeable(os.path.normpath(cwd))`.
  - The payload is `f"cd -- '{os.path.normpath(cwd)}'\n"`. `normpath` is what kitty's `abspath` does
    to an absolute path, so the directory the shell enters is the one kitty would choose.
  - Everything else falls back. kitty's expansion of an absolute, `$`-free path is the identity, and
    `abspath` is `normpath`, so the two paths agree by construction, with no guess about either
    process's environment.
- **Alternatives, weighed.**
  - *Expand in the launcher*, the first draft: **rejected**. It expands with the launcher's
    environment and resolves against the shell's directory, while kitty uses its own. The review's
    counterexample is the first draft's own tilde test: it changed HOME after kitty started, and
    pane 1 would have landed elsewhere.
  - *One shared context: expand every pane in the launcher*: **rejected**.
    - It changes what every other pane's `cwd` means, which the "every other pane is unchanged"
      truth forbids.
    - kitty would then expand a second time any `$` the result still holds.
  - *Chosen: the argv fallback.* It is equivalent by construction, adds no expansion code, and
    removes the `./` and `-`-option hazards at the same time, because no relative target is ever
    typed.
- **Cost.** A recipe whose pane 0 sets `cwd = "~/code/app"` now opens a new tab instead of filling the
