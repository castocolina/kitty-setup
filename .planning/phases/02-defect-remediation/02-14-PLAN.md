- **Research.**
  - zsh's `compinit` scans every directory on `fpath` for files named `_*` whose first line is
    `#compdef <names>`, and registers them for autoload.
  - argcomplete's zsh shellcode begins `#compdef my-kitty` and supports autoload: it checks
    `$zsh_eval_context == *func` and runs `_python_argcomplete "$@"` when loaded as a function.
  - A file on `fpath` therefore registers whenever a later `compinit` **scans `fpath`**, with no
    dependence on where the block sits. `compinit -C` does not scan: when a dump exists it sources it
    unconditionally (zsh 5.9.2 `compinit:491-517`), and the dump's `_comps=(…)` replaces the table.
- **Experiment.** Hermetic: `zsh -i`, with `HOME` and `ZDOTDIR` set to a scratch directory and a narrow
  `PATH`. Two starts per shape, so the second reads the first one's `.zcompdump`.
  - Today's design:

      `_python_argcomplete` in both starts, and doctor FAILs it. That is a false red.
    - The block first, then a plain `compinit` or a framework file running one, registers nothing.
    - The block last, as install leaves it, puts `~/.local/bin` ahead of SDKMAN and pyenv.
  - Option **O1**, a guarded PATH line kept last:
    - appending `~/.local/bin` demotes it below `/usr/bin`, so a distro binary shadows ours;

**WR-06, the rc half. Decision: lossless rc I/O in `path_integration.py`, and `errors="surrogateescape"`
on doctor's read-only rc read.**
- Measured at `1cbcaaa`: with a `.bashrc` or `.zshrc` of `b"# caf\xe9 alias\n…"`,
  `ensure_local_bin_in_path` and `_check_completion` both raise an uncaught `UnicodeDecodeError`.
- Real bash and real zsh source such a file without complaint.
- `surrogateescape` alone is **not** byte-exact. Measured 2026-11-03 on Python 3.12.12, with
  `b"# caf\xe9 alias\r\nexport A=1\r\nlone\rcr\nlf only\n"`:
  - `read_text(errors="surrogateescape")` then `write_text(errors="surrogateescape")` gives back
    `\n` everywhere, because both apply universal newlines;
  - `Path.read_text(newline="")` raises `TypeError` on 3.12, the project floor;
  - `read_bytes().decode("utf-8", "surrogateescape")` then `write_bytes(text.encode("utf-8",
    "surrogateescape"))` is byte-exact;
  - the existing `find_block` and `_splice_lines` keep every CRLF and lone CR outside the block
    once the I/O is lossless, because both split with `splitlines` and `_splice_lines` keeps the ends.
- So `path_integration.py` reads and writes the rc through two small helpers, one `read_bytes` decode
  and one `encode` `write_bytes`, both with surrogateescape. No `read_text`, `write_text` or `open` is
  left in the module.
- Doctor only judges the rc and never writes it, and both predicates `rstrip` each line. So its
  `read_text(encoding="utf-8", errors="surrogateescape")` is enough there.
- Rejected: catching the error and reporting "not UTF-8". That refuses a file the user's shell
  accepts.
