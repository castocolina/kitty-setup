## Completion mechanism (R1.1)

Scouting result presented before the question: the helper **does** exist at
`~/.local/share/uv/tools/kitty-setup/bin/register-python-argcomplete`, but `uv tool install`
exposes only the package's own entry point, so it never reaches PATH. The `~/.bashrc` block is
present and correct, guarded with `command -v register-python-argcomplete` — which is why
completion fails silently while doctor reports it.

| Option | Description | Selected |
|--------|-------------|----------|
| Static completion file | Generated at install into `~/.local/share/kitty-setup/`, sourced by the rc block; no runtime helper | ✓ |
| Absolute path to the venv helper | Point the eval line at the uv tool venv and have doctor look there | |
| `uv tool install argcomplete` | Install the helper as a second global tool so it lands on PATH | |
| Drop the check | Abandon tab completion | |

**User's choice:** Static completion file.
**Notes:** Chosen because it is the only option this project owns end-to-end — the alternatives depend on a uv-internal path that uv may move, or add an unrelated global tool to the host. Side benefit: no per-shell-startup subprocess. Cost recorded in D-03: the file must be regenerated when the CLI surface changes, so generation belongs to the install path.

## Install log fate (R1.7)

| Option | Description | Selected |
|--------|-------------|----------|
| Delete it | Remove `_record_install_log`; reword R1.7 from "relocate" to "remove" | ✓ |
| Relocate to XDG state | `~/.local/state/kitty-setup/install.log` with path + version, as R1.7 originally specified | |

**User's choice:** Delete it.
**Notes:** Today it writes only the version string to `_repo_root()/tmp/install.log`, which resolves *inside the uv tool venv* once installed. Nothing reads it, and the kitty-install spec that required it became frozen history in Phase 1 — so the requirement text was the thing to change, not the code's location. R1.7 and the ROADMAP criterion were reworded to match.

## Color strictness (R1.7)

| Option | Description | Selected |
|--------|-------------|----------|
| Empty = absent, strict passthrough | Empty/whitespace emits no kitten argument; passthrough narrowed to real `rgb:`/`rgba:`/functional forms | ✓ |
| Empty = error | Raise `ColorError` on empty/whitespace | |

**User's choice:** Empty = absent, strict passthrough.
**Notes:** "Absent" matches the recipe loader's existing empty-string→`None` convention, so the two paths stop disagreeing; raising would break a recipe that spells out `bg = ""`. The passthrough narrowing is the part that fixes a real hole — today anything containing `:` or `(` skips validation, so `foo:bar` reaches kitty and can half-build a scene.
